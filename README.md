# シフト自動作成

キャリアショップ向けに、スタッフごとの戦力ポイントから月のシフト表を自動で作るブラウザアプリです。サーバーは不要で、データはブラウザ（localStorage）にだけ保存されます。

## 守る条件

- 毎日、出勤者の戦力ポイント合計が必要ポイント以上
- 「絶対」の希望休の日は出勤しない。「できれば」の希望休は、条件を満たせる範囲でなるべく叶える
- 3日連続では出勤しない（2連勤まで）。前月末の連勤も引き継ぐ

## 使い方

```sh
npm run build    # 単体で開ける dist/shift.html を作る（配布用）
npm start        # http://localhost:8000 を開く（index.html を直接開いても動きます）
npm test         # 計算部分のテスト
npm run test:e2e # ブラウザでの操作テスト（要 Playwright。スタッフ追加・希望休・Excel出力・印刷など）
```

1. スタッフと戦力ポイント、必要ポイント（平日／土日祝など高めの日）を設定する
2. 「希望休の入力」でスタッフごとに3日まで選び、「絶」（絶対休み）か「△」（できれば休み）をボタンで切り替える。4日以上は「希望休を入れる」モードでセルをタップ（押すたびに 絶対→できれば→なし）
3. 「自動作成」を押す。押すたびに条件を満たす別の案が出る
4. 「出勤を直す」モードで手直しすると、不足・3連勤がその場で表示される
5. 月の途中で変更が出たら、希望休などを直して「作成する範囲」で開始日を選び、「◯日以降を作り直す」を押す。選んだ日より前（表で薄く表示）は今の表のまま動かず、その日以降だけを組み直す。直前までの連勤や、すでに出勤した日数の偏りも考慮される
6. 完成したら「印刷」または「Excel」（画面の表と同じ見た目の .xlsx。戦力ポイントは載りません）でスタッフに共有する

土日と祝日（振替休日・国民の休日を含め、カレンダーどおり）は、必要ポイントが多めの日になります。日付をタップすると「高め／通常」を切り替えられます。必要ポイントの数字は日ごとに書き換えられます。

## 公開（GitHub Pages）

デフォルトブランチに反映されるたびに、`.github/workflows/pages.yml` がテストとビルドをして `dist/shift.html` を GitHub Pages に公開します。公開されるのはこのHTML1枚だけです。入力内容は各自のブラウザにだけ保存され、サーバーには送られません。最初の1回だけ、リポジトリの Settings → Pages → Build and deployment の Source を「GitHub Actions」にしてください。

## 計算のしくみ（`solver.js`）

「各人が何日連続で出勤中か（0〜2）」を全員分まとめた状態を使い、月末まで条件を満たし続けられるかを厳密に調べます。条件を満たす表があれば必ず見つかり、無ければ最初に破綻する日と、その日に出られる最大ポイントを返します。満たす表の中から、余剰ポイントと出勤日数の偏り（土日祝を含む）が小さいものを選びます。

途中から作り直す `solveFrom` は、固定する日までの末尾の連勤と出勤日数（`workBase`／`highBase`）を数えたうえで、残りの日だけを `solve` で解きます。

条件を増やすときは、`allowedMask`（その日に出られる人の制限）と `feasible` に足すのが基本です。スタッフは10人までを想定しています。
